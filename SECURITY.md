# Security policy

This is a portfolio project. Nothing in it is deployed, and it holds no real customer data: the
company (Lumenfield Freight) is fictional, every task is generated by `costroute/tasks.py`, and the
personal data in some tasks is fake (`example.com` addresses, UK phone numbers reserved for fiction).

## Report a vulnerability

Please report privately through GitHub: open the **Security** tab and choose **Report a vulnerability**
(private vulnerability reporting is on). Please do not open a public issue. First reply within a week.

## Controls in place

- Secret scanning with push protection, Dependabot alerts and security updates
- CodeQL (`security-and-quality`) on every push and weekly
- gitleaks over the full git history in CI
- Every GitHub Action pinned to a commit SHA; workflow tokens are read-only
- `main` is protected: no force-push or deletion, and pull requests need the CI checks
- The deploy workflow is manual, gated by `DEPLOY_ENABLED`, and logs in with OIDC (no client secret)
- No pickled model is loaded: the router retrains from committed data at start-up
- Prompts with personal data are never sent to the non-local tier (gated in CI at 0 violations)
